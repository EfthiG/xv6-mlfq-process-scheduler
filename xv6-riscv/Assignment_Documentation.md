# Τεκμηρίωση 2ης Εργασίας

## 1o ζητούμενο: getpinfo(struct pstat *) & struct pstat
Για την εξαγωγή πληροφοριών διεργασιών από τον kernel προς τον user χώρο,δεν χρησιμοποιήθηκε απευθείας η struct proc, καθώς αυτή περιέχει kernel-only πεδία και τύπους που δεν είναι προσβάσιμοι από προγράμματα χρήστη.
Αντί αυτού, υλοποιήθηκε ένας ενδιάμεσος μηχανισμός αντιγραφής:

- ο kernel συλλέγει πληροφορίες από τον πίνακα proc[],

- τις αντιγράφει σε μια νέα δομή δεδομένων (struct pstat),

- και επιστρέφει τη δομή αυτή στον user χώρο μέσω νέας κλήσης συστήματος.

### struct pstat

**Αρχεία**
- Προστέθηκε το αρχειο user/pstat.h, το οποίο περιέχει την νέα δομή και είναι ορατό στον user χώρος

**Σχεδιασμός δομής**
- Χρησιμοποιούνται παράλληλοι πίνακες μεγέθους NPROC, ώστε κάθε index i να αντιστοιχεί απευθείας στη θέση proc[i] του kernel.

- Το πεδίο inuse[i] δηλώνει αν η συγκεκριμένη θέση αντιστοιχεί σε υπαρκτή διεργασία ή σε slot με κατάσταση UNUSED.

- Η struct pstat λειτουργεί ως snapshot της κατάστασης των διεργασιών τη συγκεκριμένη χρονική στιγμή.

### system call getpinfo

**Αρχεία**
- kernel/sysproc.c -> υλοποίηση της sys_getpinfo
- kernel/syscall.h -> προσθήκη νέου syscall number
- kernel/syscall.c -> αντιστοίχιση syscall number με handler
- user/user.h -> δήλωση της συνάρτησης για χρήση από user προγράμματα
- user/usys.pl -> παραγωγή του αντίστοιχου stub

**Εσωτερική Λειτουργία**
1. Ανάγνωση ορίσματος
2. Δημιουργία τοπικού snapshot δημιουργείται τοπική μεταβλητή struct pstat st στον kernel.
3. Αρχικοποιείται με memset ώστε όλα τα inuse[] να ξεκινούν από 0.
4. Σάρωση του πίνακα διεργασιών
5. Φιλτράρισμα UNUSED διεργασιών:   Αν p->state == UNUSED, το slot αγνοείται.
                                    Αν όχι, το slot θεωρείται ενεργό και: st.inuse[i] = 1
                                                                          Αντιγράφονται τα στοιχεία  
6. Μετατροπή κατάστασης διεργασίας. Η kernel κατάσταση (p->state) μετατρέπεται σε νέα user-defined enum (PST_*). Έτσι αποφεύγεται η έκθεση kernel enums στον user χώρο.
7. Ανάγνωση parent pid υπό το wait_lock, ώστε να αποφευχθούν race conditions
8. Αντιγραφή στον user χώρο με copyout



## 2ο ζητούμενο: user πρόγραμμα ps

**Αρχεία**
- user/ps.c -> νέο αρχείο, υλοποίηση του προγράμματος χρήστη ps
- user/Makefile -> προσθήκη του ps στη λίστα των user programs ώστε να μεταγλωττίζεται
- user/user.h -> δήλωση της getpinfo ώστε να είναι ορατή στο ps

**Εσωτερική Λειτουργία**
1. Δημιουργείται μια μεταβλητή struct pstat st στον user χώρο που θα γεμίσει από τον kernel μέσω της getpinfo
2. Σάρωση των entries (αν st.inuse[i], αγνοεί τα slots που δεν αντιστοιχούν σε ενεργές διεργασίες)
3. Εκτύπωση πληροφοριών

***Διαχείριση κατάστασης διεργασίας**
Η κατάσταση διεργασίας (state) μεταφέρεται από τον kernel ως ακέραιος αριθμός (PST_* enum).
Το ps είναι υπεύθυνο να μετατρέψει αυτή την αριθμητική τιμή σε αναγνώσιμη μορφή.
Για τον σκοπό αυτό, χρησιμοποιήθηκε αντιστοίχιση τύπου:
   PST_RUNNING:  "RUNNING";
   PST_RUNNABLE: "RUNNABLE";
   PST_SLEEPING: "SLEEPING"; 
Η μετατροπή αυτή γίνεται στον user χώρο, ώστε ο kernel να παραμένει ανεξάρτητος από οποιοδήποτε format εξόδου.

## 3ο ζητούμενο: MLFQ Scheduler (Multilevel Feedback Queue)

### Επέκταση της struct proc ###
**Αρχεία**
- kernel/proc.h -> Στη δομή struct proc προστέθηκαν νέα πεδία που σχετίζονται με την προτεραιότητα και το time slice των διεργασιών

### Αρχικοποίηση προτεραιοτήτων και Υλοποίηση επιλογής διεργασίας στον scheduler() ###
Ακολουθείται ο κανόνας του MLFQ ότι κάθε νέα διεργασία ξεκινά από την υψηλότερη προτεραιότητα

**Αρχεία**
kernel/proc.c

- Στη allocproc() και στο kfork() κάθε νέα διεργασία ξεκινά με:
                p->priority = 0;
                p->ticks_used = 0;
                p->wait_ticks = 0;

- Ο scheduler τροποποιήθηκε ώστε να εξετάζει πρώτα υψηλότερες προτεραιότητες και να εφαρμόζει round-robin μέσα σε κάθε επίπεδο.
    *Για κάθε επίπεδο, διατηρείται δείκτης rr_start[prio] ώστε να συνεχίζεται το round-robin από το σωστό σημείο.

### Χειρισμός timer interrupts ###

**Αρχεία**
- kernel/trap.c -> παρόμοιας λογικής αλλαγές στην διαχείρηση ticks στις συναρτήσεις usertrap() και kerneltrap()
- kernel/proc.c -> προσθεση helper συναρτήσεων 

1. *Aging*
Σε κάθε timer tick καλείται:
        mlfq_aging();

Η συνάρτηση αυξάνει wait_ticks για RUNNABLE διεργασίες, αν ξεπεραστεί 10 * quantum, αυξάνει την προτεραιότητα, αποτρέπει starvation χαμηλής προτεραιότητας διεργασιών.

2. *Έλεγχος quantum και demotion*

Το quantum υπολογίζεται με mlfq_timeslice(p->priority)
Αν ticks_used >= quantum η διεργασία υποβιβάζεται σε χαμηλότερη προτεραιότητα (εκτός αν είναι ήδη στο 3), μηδενίζεται το ticks_used, καλείται yield() για επαναχρονοπρογραμματισμό.


3. *Preemption από υψηλότερη προτεραιότητα*

         exists_runnable_higher_than(curprio)
τότε:
η τρέχουσα διεργασία παραδίδει άμεσα τη CPU (yield()), ακόμα και αν δεν έχει εξαντλήσει το quantum της
